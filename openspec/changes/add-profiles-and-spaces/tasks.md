# Tasks

Groups 1 to 5 change the engine key, so build the engine first and push docs afterwards, as `CLAUDE.md` describes. "CI" is the merge gate in `ci.yml`. "By hand" means the owner launches a test build of the branch; behaviour compared with Arc is checked there with `tests/probe/`. `quality.yml` runs on the branch before merging (`gh workflow run quality.yml --ref <branch>`). D-numbers are `design.md`'s decisions; `arc-reference.md` has Arc's measurements and wording.

Suggested order: 1, then 2 to 5 in order with one engine build at 5.7. Groups 6 and 7 can start in `ClairUI` against `FakeHost` and `FakeBrowser` as soon as 1 is done, while the engine builds. Group 8 is last.

Read `design.md` in full before starting. Verify every Chromium call it names against the engine workspace's source before using it, and update the design if one differs.
