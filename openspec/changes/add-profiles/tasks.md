# Tasks

Groups 1 and 2 change the engine key, so build the engine first and push docs afterwards, as `CLAUDE.md` describes. "CI" is the merge gate in `ci.yml`. "By hand" means the owner launches a test build of the branch; behaviour compared with Arc is checked there with `tests/probe/`. `quality.yml` runs on the branch before merging (`gh workflow run quality.yml --ref <branch>`). D-numbers are `design.md`'s decisions; "`add-spaces` D*n*" and "`share-tabs` D*n*" are decisions in `openspec/changes/archive/2026-11-12-add-spaces/design.md` and `openspec/changes/archive/2026-11-13-share-tabs-across-windows/design.md`, and `add-spaces`' `arc-reference.md` has Arc's wording and measurements.

Suggested order: 1, then 2. Build the engine once at 2.5 to prove the full-screen cover before the rest of group 2 depends on it, and again at 2.12. Group 3 can start in `ClairUI` against `FakeHost` and `FakeBrowser` as soon as 1 is done, while the engine builds. Group 4 is last.

Read `design.md` in full before starting. Verify every Chromium call it names against the engine workspace's source before using it, and update the design if one differs.
