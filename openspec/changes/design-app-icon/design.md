# Design

## Context

The motivation is in `proposal.md` and the required behaviour is in `specs/app-icon/spec.md`.

- **Where Chromium's icon lives.** On macOS, Chromium's bundle icon comes from two files in `chrome/app/theme/chromium/mac/`:
  - `Assets.car`, the compiled asset catalog that macOS 26 uses for its icon appearances
  - `app.icns`, the classic icon file
- **How Helium replaces them.** Helium keeps an Icon Composer source (`AppIcon.icon`: `icon.json` plus an SVG) and commits a precompiled `Assets.car` and `app.icns`. A resource list (`platform_resources.txt`) copies both over Chromium's files at prepare time.
- **Change 1's plan.** `ship-plain-ungoogled-build` design D2 and task 2.4 plan the same approach with a placeholder icon.
- **Tooling.** Compiling a `.icon` document needs `actool` from Xcode 26. The hosted macOS runners and the release runner both have Xcode 26.6. The development machine never runs `prepare`.
- **Design record.** The concepts, sizes and variants explored on 2026-10-27 are on the owner's private concept page, <https://claude.ai/artifact/3BJdVBWhpfHk7As4UauYFR>. The chosen variant is "B1 at 72%".

## Goals / Non-Goals

**Goals:**
- One committed vector source for the mark. Every icon file and logo image is generated from it, and the generated files can be regenerated without design work.
- The icon looks right in every macOS 26 appearance without a custom background.

**Non-Goals:**
- Per-size artwork on any macOS version. Icon Composer documents don't support it, and `actool` renders the older-macOS images from the same vector source (D4).
- Animated or seasonal icon variants.

## Decisions

### D1. Canonical geometry

The mark is drawn in a 100 × 100 drawing space centered on (50, 50) and mapped onto Icon Composer's 1024 px canvas. That canvas is the icon tile itself. The 824 px tile with a 100 px margin exists only in exported icons, such as `actool`'s `.icns` and the spec's 1024 px rendering. The mapping `translate(9.36 -11.64) scale(10.4727)` produces these values:
- **Size:** the ring's outer edge (radius 35.2 drawing units) is 737 px across, 72% of the tile.
- **Offset:** the ring's center lands at (533, 512), so the mark sits 21 px (about 2% of the tile) right of center.

A first version used an 824 px tile inside the 1024 px canvas, and `actool` rendered the ring at only 58% of the tile. Measuring `actool`'s output is how the size is checked.

```svg
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 1024 1024">
  <g transform="translate(9.36 -11.64) scale(10.4727)" fill="none" stroke="#000" stroke-linecap="round">
    <!-- ring layer -->
    <path stroke-width="6.4" d="M74.51 29.43 A32 32 0 1 0 74.51 70.57"/>                       <!-- ring, gap +-40 deg -->
    <path stroke-width="3.6" d="M74.51 70.57 C80.43 66.02 81.08 58.22 75.88 55.62 C71.97 53.67 68.07 56.92 70.02 60.43"/> <!-- curl -->
    <path stroke-width="3.6" d="M74.51 29.43 C77.31 27.87 79.13 25.92 79.39 23.71"/>          <!-- flick -->
    <!-- inlay layer -->
    <path stroke-width="2" d="M68 34.89 A23.5 23.5 0 1 0 68 65.11"/>                           <!-- hairline -->
    <circle cx="26.5" cy="50" r="2.6" fill="#000" stroke="none"/>                               <!-- bead -->
  </g>
</svg>
```

The geometry is committed as `resources/icon/geometry.svg`. The layer SVGs are filled outlines of those strokes, like the filled paths in Helium's layer, and are generated by `resources/icon/make_layers.py` (standard-library Python). It draws the ring and hairline as exact arcs with round caps and samples the curl and flick densely. Any redraw edits `geometry.svg` and the constants in `make_layers.py` together, then regenerates the layers.

**Alternative considered:** a solid, filled mark like Dia's or Safari's. Rejected: the open ring with fine inner detail is the chosen look, and the 72% size gives the line work enough presence in the Dock.

### D2. Icon Composer document

`resources/icon/AppIcon.icon/`:
- **`icon.json` background:** the background fill is `automatic` in every appearance, which gives the system's default light and dark backgrounds the owner asked for.
- **Group 1, the ring layer** (ring, curl and flick): glass on, specular on, neutral shadow. Its fill is a vertical gold gradient specialized by appearance. The starting values below come from the concept page and are tuned by eye in Icon Composer:
  - light: `#EBCB7A` to `#9A6A1C`, deeper so it holds contrast on the light background
  - dark: `#FBE6A6` to `#B5852F`
  - tinted and clear: no fill specialization, so the system recolors the mark
- **Group 2, the inlay layer** (hairline and bead): the same fills, glass off, so it reads as fine engraving under the glass ring.

**Alternative considered:** baking the gold gradient into the SVG. Rejected, because fills set in `icon.json` can be specialized per appearance and are replaced cleanly in the tinted and clear appearances.

### D3. Build-time compile instead of committed binaries

`./build.sh prepare` runs `scripts/compile-icon.sh <AppIcon.icon> <out-dir>`. It calls `xcrun actool` with `AppIcon` as the app icon, a minimum deployment target of 15.6 and the macOS platform. `actool` writes `Assets.car` and `AppIcon.icns`, and the script renames the latter to `app.icns`. The resource-replacement step from change 1 task 2.4 then copies both files into `chrome/app/theme/chromium/mac/`. At the pinned Chromium 156.0.8078.47, that folder holds exactly these two compiled files, plus Chromium's own `AppIcon.icon` and `Assets.xcassets` sources, which the build doesn't compile. Chromium's `app-Info.plist` names them through `CFBundleIconFile = app.icns` and `CFBundleIconName = AppIcon`, which match `actool`'s output.

**Why compile at build time:** Helium commits `Assets.car` because compiling it "requires a very specific environment". Clair's CI runners already are that environment (Xcode 26.6). Compiling there keeps the source the single truth and avoids a binary that can drift from it.

**Alternative considered:** Helium's way, committing `Assets.car` compiled on the owner's Mac. It is kept as the fallback if `actool` fails on the hosted runners (see Risks). Change 1's D2 and task 2.4 describe committed binaries today, so this change updates them to the compile step.

### D4. macOS 15 fallback and small sizes come from `actool`

A trial compile on 2026-10-27 (Xcode 27.2, deployment target 15.6) showed what `actool` produces from the `.icon` source:
- **Pre-Tahoe images:** `Assets.car` contains pre-Tahoe icon images for the light, dark and tintable appearances.
- **A matching `.icns`:** `actool` writes an `.icns` with 16, 32, 128 and 256 px images at 1x and 2x, rendered with the gold gradient, the glass highlights and the system's light tile.
- **Plist keys:** its partial `Info.plist` sets `CFBundleIconName = AppIcon`, so macOS 15 takes its icon from the catalog.

So macOS 15.6 shows `actool`'s rendering of the same source, and Clair ships no hand-made fallback. At 16 px the hairline and bead fade, but the ring and curl stay clear, which is what the spec's small-size requirement asks for.

**Alternative considered:** a committed fallback iconset rendered with `rsvg-convert`, with a simplified 16 and 32 px drawing, added to the catalog as an `AppIcon.appiconset` so that macOS 15 would prefer it. Rejected by the owner on 2026-10-27: it adds tooling and files for a difference that only shows at 16 and 32 px on macOS 15, and its flat rendering would not match the glass look.

### D5. Product logos

The file list comes from Helium's `resources/helium_resources.txt`, checked file by file against Chromium 156.0.8078.47 through the GitHub API, without a checkout. Linux-only paths are dropped. Two of Helium's paths, `chrome/app/vector_icons/browser_logo.icon` and `components/omnibox/browser/vector_icons/product_chrome_refresh.icon`, don't exist at this tag and are left out.

| Chromium file(s) | Size | Source |
|---|---|---|
| `chrome/app/theme/chromium/product_logo_{16,24,48,64,128,256}.png` | as named | `logo.svg` |
| `chrome/app/theme/default_100_percent/chromium/product_logo_{16,32}.png` | 16, 32 | `logo.svg` |
| `chrome/app/theme/default_200_percent/chromium/product_logo_{16,32}.png` | 32, 64 | `logo.svg` |
| `chrome/app/theme/chromium/product_logo.svg` | vector | `logo.svg` |
| `chrome/app/theme/chromium/product_logo_22_mono.png` | 22 | `logo-mono.svg` |
| `components/resources/default_{100,200}_percent/chromium/product_logo.png` | 171×32, 342×64 | `wordmark.svg` |
| `components/resources/default_{100,200}_percent/chromium/product_logo_white.png` | 171×32, 342×64 | `wordmark-white.svg` |
| nine `.icon` vector icons (D6) | their own canvases | `make_layers.py` |

The source files are:
- **`logo.svg`:** the full mark (ring layer and inlay) in a baked gold gradient on a transparent background, fitted to its square canvas.
- **`logo-mono.svg`:** the ring layer only, in `#222222`, which is the near-black of Chromium's mono logo. The inlay is left out because it vanishes at 22 px.

`scripts/render-icon-images.sh` renders the PNGs with `rsvg-convert` from Homebrew, following `resources/icon/product-logos.txt`. The owner chose to render on the development machine and commit the PNGs, because they change only when the artwork does. The resource-replacement step copies them.

### D6. Vector icons

Chromium draws nine of its product icons from `.icon` files, its own vector format, in whatever single color the UI asks for:
- `chrome/app/vector_icons/{browser_logo_old,chrome_product}.icon`
- `components/omnibox/browser/vector_icons/{chrome_product,product_chrome_refresh_old,product_old}.icon`
- `components/vector_icons/chromium/{product,product_refresh}.icon`
- `ui/message_center/vector_icons/{chrome_product,product_old}.icon`

`make_layers.py` writes these from the same geometry. Each file keeps the canvas sizes Chromium's version declares (15, 16, 24, 32 or 96, and both 32 and 16 in `product_old.icon` in the omnibox folder). The mark is fitted to each canvas.
- **Canvases under 32:** only the ring layer, because the hairline would be thinner than a pixel.
- **Canvases of 32 and above:** the full mark.
- **Colour:** `product_refresh.icon` is Chromium's only colored one, so it gets a single gold `PATH_COLOR_ARGB`. The rest stay colorless and take the UI's color.

Each shape is its own `NEW_PATH` with `FILL_RULE_NONZERO`, because the format fills even-odd by default and the curl and flick overlap the ring. Paths use `MOVE_TO`, `LINE_TO`, `ARC_TO` and `CLOSE`, which all exist in Chromium's vector-icon format. Generated files are committed and copied by the resource-replacement step. Chromium compiles them into C++ during the build, so a malformed file fails the build.

### D7. Wordmark

`resources/icon/make_wordmark.py` writes `wordmark.svg` and `wordmark-white.svg` on a 171×32 canvas:
- **Mark:** the gold mark at the left, its ring 28 px tall and centered vertically.
- **Text:** "Clair" set in Albert Sans Medium, with a cap height of about 17 px on the canvas.

The text is converted to outlines with `fontTools`, from the variable Albert Sans font (SIL Open Font License 1.1) instanced at weight 500, so the SVGs contain no `<text>` and render the same anywhere. The text is `#4A4741` in `wordmark.svg` and white in `wordmark-white.svg`, and the mark stays gold in both. The font file is fetched by the script when the wordmark is regenerated and is not committed. Albert Sans is credited in `CREDITS.md`.

**Alternatives considered:** Marcellus (the concept page's display serif) and showing the mark only. The owner chose Albert Sans.

### D8. Originality

The mark's geometry is original. The gold palette and the light-against-shadow idea are inspired by *Clair Obscur: Expedition 33*, and no art, emblem or wordmark from the game is used or traced. The sunburst "crown" explored as variant B3 was modelled loosely on stepped-ray Art Deco metalwork. If it is ever used as a secondary brand element (for example a DMG background), it needs its own original drawing.

## Risks / Trade-offs

- **[`actool` cannot compile `.icon` on the hosted runner image]** → Fall back to D3's alternative: compile on the owner's Mac and commit `Assets.car`, with the same copy step.
- **[The runner's `actool` renders older-macOS images differently from the trial compile]** → Task 3.1's test checks the compiled outputs on CI, and task 4.5 checks the result on macOS 15.6.
- **[Gold has low contrast on the light background]** → Use the deeper light-appearance gold and the neutral shadow. Check it in the Dock against a bright wallpaper before marking the work done.
- **[Hand-written `icon.json` drifts from Icon Composer's format]** → The owner opened it in Icon Composer without warnings on 2026-10-27 and approved it unchanged. Any later edit made in Icon Composer is saved from there and committed.
- **[The optical offset is a judgment call]** → The spec allows a 12 to 22 px range on the 1024 px canvas, so a later nudge doesn't need a spec change.

## Migration Plan

Nothing has shipped, so there is no migration. If the new icon breaks a build, revert to change 1's placeholder by pointing the resource-replacement step back at it.
